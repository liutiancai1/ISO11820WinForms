# 第11章 软件部署与发布管理

> 经过前十章的完整开发流程——可行性分析、需求定义、架构设计、详细设计、编码实现、测试验证和技术研究——软件终于可以交付了。但"在开发机上运行正常"不等于"在工控机上也能跑"。
>
> 工业软件的部署比普通软件复杂得多：工控机可能没有网络、没有安装.NET Runtime、串口号与开发机不同、数据库需要初始化。本章将给出一份完整的部署指南，确保软件顺利落地到工业现场。

## 学习目标

- **理解** 工业软件部署环境的特殊性与规划方法
- **掌握** .NET桌面应用程序的打包与发布流程
- **学会** 数据库部署与配置文件管理策略
- **了解** 用户操作手册编写规范与培训要点
- **能够** 独立完成一次完整的现场部署

## 11.1 部署环境规划

工业软件的部署环境比通用软件更复杂——不仅涉及计算机本身，还涉及与硬件设备的连接。

### 11.1.1 硬件环境

| 配置项 | 推荐规格 | 说明 |
|--------|----------|------|
| **工控机** | 无风扇IPC，Intel i5+ | 减少灰尘吸入，保证多线程性能 |
| **内存** | 8GB+ | 长时间运行的数据缓存需求 |
| **硬盘** | 工业级SSD，256GB+ | 抗震，适合频繁读写日志和CSV |
| **串口** | RS-485/RS-232 | 需确认数量，推荐带光电隔离的USB转串口 |
| **显示器** | 触摸屏 | 第8章的SPA界面专为触摸操作设计 |

### 11.1.2 软件环境

| 配置项 | 推荐方案 | 说明 |
|--------|----------|------|
| **操作系统** | Windows 10/11 IoT Enterprise LTSC | 不自动更新重启，适合工业长期运行 |
| **运行时** | .NET Desktop Runtime 6.0.x | 部署机只需Runtime，不需SDK |
| **数据库** | SQL Server Express 2019/2022 | 免费，支持服务模式运行 |
| **串口驱动** | CH340 / FT232 | 根据实际转换器芯片安装 |

> 📘 **知识拓展：为什么选LTSC而不是普通Windows？**
>
> 普通Windows会在夜间自动更新重启。想象一下：一场30分钟的不燃性试验进行到第25分钟，Windows突然弹出"正在更新，请不要关闭电源"——这在工业现场是不可接受的。LTSC版本不包含预装应用（Xbox、Cortana等），且更新完全可控。

## 11.2 应用程序发布

### 11.2.1 发布模式

回顾第6章CI/CD中`dotnet publish`的配置——部署时有两种模式可选：

| 模式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **框架依赖** | 发布文件小 | 需目标机安装Runtime | 可联网的环境 |
| **Self-Contained** | 无需安装任何环境 | 文件巨大（~150MB） | 第6章提到的离线车间 |

> ⚠️ **注意：生产环境务必用Release模式**
>
> Debug模式包含调试符号，运行效率低，且可能暴露源码路径信息。在`dotnet publish`或VS发布向导中，Configuration必须选择**Release**。

### 11.2.2 安装方式

| 方式 | 操作 | 推荐场景 |
|------|------|----------|
| **绿色免安装** | 将发布文件夹整体复制到`D:\ISO11820_System` | 调试和内部使用 |
| **安装包** | 使用Inno Setup制作，自动检测Runtime、创建快捷方式 | 正式交付客户 |

## 11.3 数据库部署与配置管理

### 11.3.1 数据库初始化

软件首次部署时数据库是空的，需要创建表结构。推荐使用SQL脚本而非自动迁移：

```powershell
# 在开发机生成发布脚本
dotnet ef migrations script -o deploy.sql

# 在部署机执行
sqlcmd -S .\SQLEXPRESS -U sa -P YourPassword -i deploy.sql
```

> 💡 **想一想**
>
> 回顾第5章的审计日志表`Sys_AuditLog`——数据库初始化时，是否需要预插入一个管理员账号？如果是，这个初始密码应该写在deploy.sql里还是让用户首次登录时设置？

### 11.3.2 配置文件管理

回顾第6章的.gitignore策略——现场配置文件不应提交到仓库。部署时需根据现场环境修改`appsettings.json`：

```json
{
  "ConnectionStrings": {
    "ISO11820": "Server=.\\SQLEXPRESS;Database=ISO11820;User Id=sa;Password=***;"
  },
  "Hardware": {
    "PidPort": "COM3",
    "PowerPort": "COM4",
    "SensorPort": "COM5"
  }
}
```

> ⚠️ **注意：密码管理**
>
> 回顾第5章的审计追踪要求——生产环境的数据库密码**不能**提交到第6章的Git仓库。应使用环境变量或加密配置文件管理敏感信息。

## 11.4 用户培训与操作手册

工业软件的用户群体通常是一线操作员，计算机水平参差不齐。详尽的操作手册和有效的培训是系统成功交付的关键。

### 11.4.1 操作手册编写

操作手册应以**任务驱动**方式编写（"如何进行一次试验"），而不是功能罗列（"菜单A有什么功能"）：

| 章节 | 内容 | 对应系统功能 |
|------|------|-------------|
| 系统概述 | 功能简介、硬件连接示意图 | — |
| 快速入门 | 开机→登录→完成一次标准试验 | 第8章的主控界面 |
| 常规操作 | 试样登记、过程监控、报告生成 | 第8章的SPA各页面 |
| 高级维护 | 传感器校准、PID参数整定、数据备份 | 第8章的工程师模式 |
| 故障排查 | 错误代码对照表、通讯故障指南 | 第5章的异常处理设计 |

### 11.4.2 分角色培训

| 角色 | 培训重点 | 时长 |
|------|----------|------|
| **操作员** | 标准试验流程、安全操作规范、现场演练 | 半天 |
| **管理员** | 配置参数修改、账号管理、日志查看 | 2小时 |

> 🔍 **案例实战：培训中最容易被忽略的环节**
>
> 很多培训只演示"正常流程"，却不教"出了问题怎么办"。操作员必须知道：如果试验进行中界面突然弹出红色警告（第5章的Alarm状态），应该先按物理急停按钮，再查看软件日志——而不是点鼠标关掉弹窗。

## 11.5 现场部署实战

以本教材的ISO 11820不燃性试验系统为例，完整演示一次现场部署流程：

| 步骤 | 操作 | 验证方法 |
|------|------|----------|
| **1. 环境检查** | 确认Windows LTSC已安装，3个USB转串口线在设备管理器中识别为COM3-5 | 设备管理器截图 |
| **2. 安装依赖** | 安装.NET 6 Runtime + SQL Server Express | 运行`dotnet --info`确认 |
| **3. 部署软件** | 复制Release文件夹到`D:\ISO11820_System` | — |
| **4. 修改配置** | 根据实际串口号修改`appsettings.json` | — |
| **5. 初始化数据库** | 执行`deploy.sql`脚本 | SSMS中确认表结构 |
| **6. 联调测试** | 启动软件，手动设定50℃，观察硬件响应 | 温控器面板显示相同值 |
| **7. 交付培训** | 向实验室主任移交操作手册，演示完整试验 | 操作员签字确认 |

> 📘 **知识拓展：发布清单（Release Note）**
>
> 每次发布应编写Release Note，记录：版本号与发布日期、新增功能列表、修复的Bug列表、已知问题、升级注意事项（如"需执行xxx.sql脚本"）。这对应第6章的语义化版本号和第7章的文档管理体系。

## 本章小结

本章完成了从开发环境到生产环境的最后一步——将软件安全、可靠地部署到工业现场。

**关键知识点**：

*   工业部署环境需要无风扇工控机、LTSC操作系统和光电隔离串口
*   发布模式选择取决于现场是否能联网安装Runtime
*   配置文件中的密码不能提交到Git仓库，应使用环境变量管理
*   操作手册要以"任务驱动"方式编写，而不是功能罗列
*   现场部署应有标准化的步骤清单，确保可复现

**与前后章节的关系**：
*   第6章搭建了CI/CD流水线 → 本章使用其产出物进行部署
*   第5章设计了审计日志 → 本章在数据库初始化时需要创建相关表
*   第8章设计了界面 → 本章的操作手册引导用户使用这些界面
*   第9章验证了代码质量 → 本章的联调测试是最终的现场验收
