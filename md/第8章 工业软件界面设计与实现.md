## 8.1 导航架构：SPA风格的主窗体

传统的 `Form.ShowDialog()` 弹窗式交互会让操作员迷失在层层叠叠的窗口中。回顾第5章的主控界面原型——它是一个**单窗口、多区域**的设计。我们用SPA（Single Page Application）风格来实现。

### 8.1.1 容器化导航

主窗体仅作为框架，包含：
*   **Header**：标题、报警栏、系统时间
*   **Sidebar**：导航菜单（试验监控、参数配置、历史报表、硬件调试）
*   **ContentPanel**：中间空白容器

所有功能页面都设计为`UserControl`而非`Form`：

```csharp
// 导航服务
public void NavigateTo(UserControl newView) {
    contentPanel.Controls.Clear();      // 移除旧页面
    newView.Dock = DockStyle.Fill;      // 充满容器
    contentPanel.Controls.Add(newView); // 添加新页面
}
```

### 8.1.2 高DPI适配

工业现场的工控机常配备4K显示器，不做适配会导致界面模糊：

```xml

  <windowsSettings>
    <dpiAwareness>PerMonitorV2</dpiAwareness>
  </windowsSettings>
</application>
```

## 8.2 实时趋势曲线绘制

不燃性试验需要实时绘制"炉温(T1)、表温(T2)、心温(T3)"三条曲线，持续30分钟，以1Hz采样共5400个点。WinForms自带的`Chart`控件数据量大时会卡顿，我们直接用**GDI+**手绘。

### 8.2.1 自定义曲线控件

```csharp
public class RealTimeTrend : Control 
{
    private List<PointF> _t1Points = new List<PointF>(2000);
    private List<PointF> _t2Points = new List<PointF>(2000);
    private List<PointF> _t3Points = new List<PointF>(2000);

    public RealTimeTrend() {
        // 开启双缓冲，消除闪烁
        this.SetStyle(ControlStyles.AllPaintingInWmPaint | 
                      ControlStyles.UserPaint | 
                      ControlStyles.OptimizedDoubleBuffer, true);
    }

    public void AddPoints(float t1, float t2, float t3) {
        float x = _t1Points.Count;
        _t1Points.Add(new PointF(x, t1));
        _t2Points.Add(new PointF(x, t2));
        _t3Points.Add(new PointF(x, t3));
        this.Invalidate(); // 触发重绘
    }

    protected override void OnPaint(PaintEventArgs e) {
        var g = e.Graphics;
        g.SmoothingMode = SmoothingMode.AntiAlias;
        
        DrawGrid(g);  // 绘制网格背景
        
        // DrawLines 批量绘制，性能是逐点 DrawLine 的 100倍
        if (_t1Points.Count > 1) g.DrawLines(Pens.Red, _t1Points.ToArray());
        if (_t2Points.Count > 1) g.DrawLines(Pens.Green, _t2Points.ToArray());
        if (_t3Points.Count > 1) g.DrawLines(Pens.Blue, _t3Points.ToArray());
        
        // 绘制 ISO 750℃ 判定红线
        float y750 = MapY(750);
        g.DrawLine(Pens.Red, 0, y750, Width, y750);
    }
}
```

> 📘 **知识拓展：为什么用DrawLines而不是DrawLine？**
>
> `DrawLines`一次传入所有点的数组，由GDI+内部批量处理，避免了5400次函数调用的开销。在工业实时绘图中，这个优化直接决定了界面是否卡顿。

### 8.2.2 曲线交互

| 功能 | 实现方式 | 说明 |
|------|----------|------|
| **滚轮缩放** | 矩阵变换`Matrix.ScaleAt()` | 以鼠标点为中心缩放X轴 |
| **游标Tooltip** | `OnMouseMove`事件 | 悬停显示(时间, 温度)数值 |
| **判定线** | 固定Y=800(750+50) | ISO标准合格阈值，红色虚线 |

## 8.3 国际化与换肤

### 8.3.1 多语言支持（.resx方案）

随着国产设备出海，软件必须支持多语言切换：

1. 将Form的`Localizable`属性设为`True`
2. 在VS属性栏切换`Language`为目标语言，修改控件文字
3. 动态切换：

```csharp
public void SwitchLanguage(string cultureCode) {
    Thread.CurrentThread.CurrentUICulture = new CultureInfo(cultureCode);
    var resources = new ComponentResourceManager(typeof(MainForm));
    foreach (Control c in this.Controls) {
        resources.ApplyResources(c, c.Name);  // 递归重载资源
    }
}
```

### 8.3.2 暗黑模式（ThemeManager）

夜班巡检时，刺眼的白色屏幕会让操作员不适。建立调色板系统，不要硬编码`Color.White`：

```csharp
public static class ThemePalette {
    public static Color BackColor { get; set; }
    public static Color TextColor { get; set; }
    
    public static void LoadDarkTheme() {
        BackColor = Color.FromArgb(30, 30, 30);
        TextColor = Color.LightGray;
    }
}
// 所有控件颜色绑定到ThemePalette，主题切换时触发ThemeChanged事件
```

> 🔍 **案例实战：暗黑模式与第5章ASM配色的关系**
>
> 第5章的ASM配色方案规定背景色为`#2D2D30`——这恰好就是暗黑模式的默认背景色。也就是说，工业HMI的标准配色天然就是"暗黑模式"，因为它能减少视觉疲劳、突出报警信息。白天模式反而是对标准的妥协。

## 8.4 工程师模式与权限管理

现场调试时，工程师可能需要绕过PID自动控制，手动输出100%功率来测试加热棒。这是**高危操作**，必须有权限锁。

### 8.4.1 设计方案

| 要素 | 设计 | 说明 |
|------|------|------|
| **隐藏入口** | 连续点击5次Logo图标 | 防止操作员误触 |
| **密码验证** | 每日动态密码（如日期格式） | 简单但有效 |
| **手动/自动切换** | 开关控件 + 警告日志 | 切入手动时自动写入第5章的审计日志 |
| **自动退出** | 关闭调试面板即退出工程师模式 | 防止忘记恢复 |

> ⚠️ **注意：手动模式的安全风险**
>
> 回顾第3章的安全性需求——急停优先级高于任何其他逻辑。即使在手动模式下，超温保护和急停功能仍然**不能被绕过**。工程师模式只允许手动控制加热功率，不允许关闭安全保护。

## 8.5 报告生成与合格判定

试验结束后，用户最关心的是："到底合不合格？"

### 8.5.1 判定逻辑可视化

根据**ISO 11820**标准，判定依据为：炉内平均温升不超过50℃。

*   **基准线**：试验开始时的平衡温度（如750℃）
*   **阈值线**：750 + 50 = 800℃（红色虚线）
*   **判定**：T1曲线从未超过阈值线 → 绿色 **[合格]**；否则红色 **[不合格]**

### 8.5.2 NPOI生成Word报告

使用NPOI库根据Word模板自动生成报告：

```csharp
public void GenerateReport(string templatePath, TestReportData data, string outputPath) {
    using (var doc = DocX.Load(templatePath)) {
        doc.ReplaceText("{{SampleId}}", data.SampleId);
        doc.ReplaceText("{{MaxTemp}}", data.MaxFurnaceTemp.ToString("F1"));
        doc.ReplaceText("{{Result}}", data.IsPass ? "合格" : "不合格");
        doc.SaveAs(outputPath);
    }
}
```

> 📘 **知识拓展：报告数据的可追溯性**
>
> 回顾第5章的审计追踪和第6章的版本控制——每份报告应记录生成时使用的软件版本号、原始数据文件路径和操作员信息。这样当客户质疑检测结果时，可以完整追溯到原始温度曲线数据。

## 8.6 混合开发：WebView2集成

WinForms的GDI+绘图强大但繁琐。如果需要复杂的统计报表或数字孪生大屏，嵌入Web技术是更好的选择。

### 8.6.1 架构分工

| 技术 | 负责领域 | 原因 |
|------|----------|------|
| **WinForms原生** | 参数设置、硬件调试、实时报警 | 强交互、低延迟 |
| **WebView2** | 历史数据看板、ECharts统计报表 | 可视化丰富、开发效率高 |

### 8.6.2 C#与JS双向通信

```csharp
// C# 注入对象给前端JS
await webView.EnsureCoreWebView2Async();
webView.CoreWebView2.AddHostObjectToScript("plcBridge", new PlcInterop());

[ClassInterface(ClassInterfaceType.AutoDual)]
[ComVisible(true)]
public class PlcInterop {
    public string GetRealtimeData() {
        var data = new { t1 = 750.5, t2 = 748.2, t3 = 749.1 };
        return JsonSerializer.Serialize(data);
    }
}
```

```javascript
// 前端JS定时读取C#数据
setInterval(async () => {
    const json = await window.chrome.webview.hostObjects.plcBridge.GetRealtimeData();
    updateECharts(JSON.parse(json));
}, 1000);
```
